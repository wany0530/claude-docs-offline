# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview
A tool that builds an **offline snapshot** of the official Claude Code docs (https://code.claude.com/docs) in **English and Korean**: collect → JSON → static HTML site (official-site-like layout), plus a single entry point. **Never translate**: the Korean side is the official `/docs/ko/<slug>.md` text; pages without one fall back to the English text with a notice. UI strings (`UI_TEXT` in the converter) are the only text written here. Python 3.9+ standard library only (no packages; uses `str.removesuffix`). User-facing usage is in `README.md`; this file covers what you need to modify and verify the code.

`output/` and `logs/` are both git-ignored (logs stay local).

## Commands
- **Full build** (needs internet, ~10 s–2 min): `python build_docs_snapshot.py [out_dir] [log_dir]`. Defaults are `output/` and `logs/` next to the script, regardless of cwd.
- **Per stage** (use a scratch folder, not `output/`):
  ```
  python docs_fetch_json.py tmp/docs.json tmp/site/assets
  python docs_json_to_html.py tmp/docs.json tmp/site
  ```
  The fetcher's optional 2nd argument is the assets folder (the build passes `.building/site/assets` so assets are saved once, straight into the site). Without it assets go next to the JSON. `docs_fetch_json.py` with no argument writes `YYYY-MM-DD/docs.json` relative to the **cwd** (unlike the build script).
- **Tests** (stdlib `unittest`, no network): `python -m unittest discover tests`. It also runs the Node tests in `tests/js/*.test.js` (`node --test`, built-in runner, nothing to install) and the Python↔JS `anchor_key` parity check; both are skipped with a message when `node` is missing. Run after touching the converter, `site_src/`, `anchor_key`/`anchorKey`, or the history/diff/build code.
- **Accessibility** is tested twice: `tests/e2e/a11y.spec.js` runs axe-core (`@axe-core/playwright`, pinned, dev only) with WCAG 2 A/AA + best-practice tags on light and dark themes, the open search dialog and the 390px layout, and exercises the keyboard (skip link, focus ring, tab arrows, search focus trap/arrows/Esc, narrow-screen TOC). Rules that came out of it: search button's accessible name must be its visible text (WCAG 2.5.3), so mobile hides the text visually, never `display:none` and never a different `aria-label`; same-role landmarks need distinct `aria-label`s; no heading level skips (TOC title is a `<p>`); light-theme muted text and callout titles are computed against their real backgrounds (see the `--mut`/`--note…--imp` variables in `style.css`); anything that can scroll horizontally must be keyboard-reachable, so the table wrapper `.table-wrap` carries `tabindex="0"` (axe `scrollable-region-focusable`; found only by CI because the fixture tables did not overflow with this PC's fonts; guarded by `TableFocusTest` in `tests/test_md_modules.py`). Headless Chromium requests no favicon, so the favicon link is guarded by `test_site.py`, not E2E.
- **Browser E2E** (dev only, Chromium): `cd tests/e2e && npm ci && npx playwright install chromium && npm test`. `playwright.config.js` builds the fixture site (`build_fixture.py` → `.site/`, git-ignored) and serves it with `python -m http.server`; `site.spec.js` also opens the same site over `file://`. `@playwright/test` is pinned to 1.61.1 (Chromium revision 1228); don't bump it without checking which browser revision it wants. Selectors and expected strings are in `site.spec.js`; the fixture is the contract.
- **Real-data invariants**: `DOCS_REAL=1 python -m unittest discover tests -p "test_realdata.py"` converts the latest `output/history/*.json.gz` (copies `output/site/assets`, ~30 s). Limits live in `tests/real_data_limits.json`. A failure on `unreviewed` means new word-match anchor fixes appeared upstream: review them, then add to `reviewed_anchors.json`.
- **CI**: `.github/workflows/test.yml` runs the unit suite on Python 3.9 and 3.14 (coverage on 3.14 only) and the E2E suite on every push/PR. First real run (2026-11-27) passed after two fixes it found: the `unit` job is pinned to `ubuntu-24.04` because `ubuntu-latest` (26.04) has no Python 3.9 build, and `.table-wrap` needed `tabindex="0"`. Ubuntu only; no macOS/Windows runner. `tests/test_compat.py` stays as the fast local static guard for the 3.9 claim (this machine only has 3.14).
- **Reading CI results without `gh`**: the repo is public, so the REST API works unauthenticated: `actions/runs?head_sha=<sha>`, `actions/runs/{id}/jobs`, `check-runs/{job id}/annotations`. Raw logs need auth, so failures must surface as annotations (`ci/run_unit.sh` emits `::error::`, Playwright uses the `github` reporter). When printing annotations on Windows set `PYTHONIOENCODING=utf-8` (the Playwright summary contains an emoji; cp949 raises). A local pass does not prove a CI pass: Linux fonts overflow layouts that fit on this PC.
- **Coverage** (dev only; `pip install -r requirements-dev.txt`, coverage 7.x needs Python 3.11+): `python -m coverage run -m unittest discover tests && python -m coverage report` (branch coverage, floor `fail_under = 95` in `.coveragerc`; 99% when it was added). `node --test --experimental-test-coverage tests/js/*.test.js` for `lib.js`. `cd tests/e2e && npm run coverage` runs the E2E suite with Chromium JS coverage (`JS_COVERAGE=1`, collected in `base.js`, merged by `js-coverage-report.js` onto the `site_src` parts; `-- --min=N` sets a floor, CI uses 90). Coverage only says a line ran. Read uncovered lines before writing a test for them (several were real behavior: spaced `- - -` rules, redirect aliases, stale `.diff` removal, clipboard fallback), and mutation-check the new test.
- **Mutation check** after touching a test or its subject: break the code on purpose, one thing at a time, and confirm the matching test fails. The first run of this found an E2E layout test that passed with the bug present (fixture cells were too short to squeeze the column). A test that cannot fail is worth nothing.
- **Diff two kept days**: `python docs_diff.py 2026-11-20 2026-11-27 [en/page]` (dates resolve to `output/history/DATE.json.gz`; paths also work).
- **Offline verification** against real data: re-run only the converter on the kept history, writing to a scratch folder, not into `output/`: `python docs_json_to_html.py output/history/YYYY-MM-DD.json.gz <scratch>/site output/site/assets` (3rd arg = where to copy assets from; skipped if `<scratch>/site/assets` exists). Expect `없는 파일 0개` (0 missing files), `헤딩 220/220` and `아코디언 N/N` Korean id matches, and about 450 anchors per language that end up as `stale` (see Invariants).
- **Visual check**: serve the site with `python -m http.server` (browser tools block `file:` URLs; the site itself works over `file://`) and compare against the official site's look. Don't pipe it into `Select-Object -First N` and then trust the exit code; the closed pipe makes it nonzero.
- Don't use `python -I`: the scripts import each other from the same folder.

## Architecture
| File | Role |
|---|---|
| `build_docs_snapshot.py` | Entry point: connectivity check → fetch → convert → change summary → swap `site/` → save history + diff → log |
| `docs_fetch_json.py` | Reads the page list from `llms.txt`, downloads each English `.md`, its official Korean counterpart, and the images/videos, writes one JSON |
| `docs_json_to_html.py` | CLI and orchestration only: reads the JSON (.json or .gz), renders every page, settles anchors, writes the two-language static site (opens via `file://`), prints the link report. `main()` signature: `[input.json(.gz) [out [assets_src]]]` |
| `docs_markdown.py` | Facade: `Renderer(InlineMixin, IdMixin, ComponentMixin, StructureMixin, BlockMixin)` owns all state (`__init__`) and `render`; re-exports the public names (`PUBLIC_API` in `tests/test_md_modules.py`). Import from here, not from the `md_*` modules |
| `md_syntax.py` | Regexes and stateless helpers: `esc`, `attr`, `heading_slug`, `anchor_key`, `strip_banner`, `plain_text` |
| `md_inline.py` | `InlineMixin`: emphasis, code, links, images, `fix_url` (docs links → relative, anchors → `N` markers when `defer_anchors`). Reads `slug, targets, assets, defer_anchors`, writes `links` |
| `md_ids.py` | `IdMixin`: heading/accordion ids (one shared numbering) and borrowing the English page's ids (`hint`, `acc_hint`). State: `ids, used_ids, head_ids, acc_ids, hint*, acc_hint*` |
| `md_components.py` | `ComponentMixin`: tabs, accordions, cards, callouts, lead text, blockquotes (`quote_block`, `tab_group`). State: `tab_n, lead_done` |
| `md_structures.py` | `StructureMixin`: tables and lists |
| `md_blocks.py` | `BlockMixin`: the block loop (`blocks`: paragraphs, headings, fences, HTML blocks) and `starts_block`. Writes `heads` |
| `docs_anchors.py` | Build-time anchor settlement (`resolve_anchor`, `resolve_anchors`), the reviewed-anchor ledger (`load_ledger`, `compare_ledger`), manual-check hints (`nearest_id`) and the `REPORT` dict the build copies into the log |
| `docs_changes.py` | Change computation shared by the log and the site: `split_sections`, `page_changes` (new/removed/edited sections, added/removed lines, char delta), `change_data(prev, new, label)` → structured data (added/removed/changed with per-language details; a page without a Korean version shows the English change in `ko`; an English-only change is not a Korean change), `changes_markdown(data, lang)` → the page's markdown (`TEXT` holds the hand-written labels). `build_docs_snapshot.summarize_change` and the converter's `changes=` argument both use it |
| `docs_site.py` | Site parts: `UI_TEXT` (the only hand-written Korean), language list, sidebar tree (`Group`, `build_nav`), address tables (`make_targets`), and the loaded `site_src/` files (`CSS`, `JS`, `PAGE` template) |
| `site_src/` | The site's real source files: `style.css`, `page.html` (a `string.Template`, `${name}` slots), and the JS parts `lib.js` (pure functions, DOM-free, exported for Node tests as `DocsLib`), `app.js` (sidebar, tabs, anchor jump, TOC, copy), `search.js`, `highlight.js`; concatenated in that order into `site/nav.js` |
| `docs_diff.py` | `open_json` (json or .gz), `diff_snapshots` (per-page unified diff, keys `en/slug` and `ko/slug`; Korean is compared only when both snapshots have it); CLI for any two kept days. Imported by the build script and the converter |
| `docs_verify.py` | Independent link checker. Re-reads only the built `en/`+`ko/` HTML with `html.parser` (never imports the converter) and checks every `a[href]` file/anchor, `img/video src`, duplicate ids, exactly one `h1`, leftover control characters; `stale-anchor` links must carry no fragment. `check(site_dir)` → `{counts, problems}`; CLI `python docs_verify.py output/site` exits 1 on any violation. The build runs it before swapping the site and fails on violations. Guarantees the target id exists, not that the section is the right one |
| `reviewed_anchors.json` | Ledger of the word-match (`strict`) anchor fixes that were reviewed (91 at 2026-11-27, `{"page#old-anchor": "new-id"}`, language prefix dropped, reviewed by Claude, not a human). It never changes link behavior: the log's `링크 검증` section lists strict fixes missing from it (`검토 필요`) or resolved to a different id. Add a pair only after checking the target page's real heading |
| `docs_common.py` | `norm` / `slug` / `ko_url`: the shared URL rules; `setup_console()`: UTF-8 + line-buffered stdout/stderr (called in each script's `__main__`, before the build's `Tee`) |
| `tests/` | `unittest` suite: markdown renderer + components, Python↔JS anchor parity, fetcher (fake `_open`/`get`/`get_bytes`: index, link classes, nav labels, assets, `main`), whole-build runs (`test_run.py`: success, offline, fetch failure, verifier violation, lock; old site must stay byte-identical), site output, independent verifier, Python 3.9 syntax guard (`test_compat.py`), real-data invariants (opt-in). `fixtures.py` = shared builders. `tests/js/` = Node tests for `site_src/lib.js`; `tests/e2e/` = Playwright browser tests + the fixture site builder |
| `reference/` | Local-only docs-site screenshot (design reference); git-ignored because it reproduces Anthropic's page |

**`docs.json`**: top-level keys `source, fetched_at, page_count, languages, nav_names_ko, nav_order, nav_name_mismatch, ko_errors, redirects, unresolved_links, non_page_links, assets_dir, asset_errors, pages[]`. Page keys: `category` (list `[tab, sidebar section, group, subgroup…]`; `_unlisted` for hidden pages), `title, url, description, content, nav_label, assets` ({remote URL: `assets/file`, shared by both languages}), `ko` (`{title, description, content, nav_label}` = official Korean page, or `null` when the official site has none) and `error` / `ko_error` on a failed fetch. `nav_names_ko` maps English tab/group/subgroup names to the Korean site's names (paired by position on each tab's first page, plus same-slug menu items); names identical in both languages are omitted. `nav_order` = `{tab: [[kind, name], ...]}` where kind is `g` (group header), `p` (page, `en/slug`) or `s` (collapsed subgroup header), in the order the official sidebar HTML lists them (`docs_fetch_json.parse_nav`). The official site interleaves subgroups with pages while `llms.txt` lists subgroups last, so `docs_site.rank_nav` re-sorts **siblings** by it; items the HTML doesn't list (children of collapsed subgroups, hidden pages) stay right after their llms.txt predecessor. Old snapshots without `nav_order` keep the llms.txt order.

**Fetch** also collects hidden pages (`_unlisted`), old-link aliases (`redirects`) and sidebar names (`nav_label`). The Korean page list is derived from the English `llms.txt` (`ko/llms.txt` does not exist): `/docs/en/` → `/docs/ko/`. A Korean URL that 404s, serves HTML, or redirects outside `/docs/ko/` (currently `changelog`, `claude-tag`) means “no Korean version” (`ko = null`, not an error); any other failure sets `ko_error` and fails the build. It deliberately skips `CHANGELOG.md`, `plugins/` and `examples/` of the GitHub repo `anthropics/claude-code` (too volatile / duplicates the docs).

**Convert** writes `<site>/en/...html` and `<site>/ko/...html` (original URL structure), `index.html` (redirect to the first English page), `nav-data-{en,ko}.js` (tab → group → page tree + `window.DOCS_UI` strings), `search-data-{en,ko}.js`, `style.css`, `nav.js` (the `site_src/*.js` parts joined). Internal docs links (English or Korean URLs) become relative paths inside the page's own language; images/videos point to the shared `assets/`. Layout follows the official site: header (logo, language switch, search button `Ctrl K`), top tab bar (`category[0]`), sidebar of the active tab (`category[2:]`; top-level groups are headers, deeper groups collapsible), a right-hand “On this page” table of contents (`#toc`, built in the browser from the article's `h2`/`h3` ids with scroll tracking; hidden when under 2 headings or below 1240px wide), serif titles, a “Copy page” button (markdown embedded as JSON in `#md-src`), per-block copy buttons. Mintlify blocks in the markdown are rendered as components: `> [tab] name` runs → tab group, `> [accordion] title` → `<details>`, `> [card] [Title](url)` runs → card grid; a `>` description directly under the h1 renders as plain lead text. Search reads the current language's `search-data-*.js` (`window.DOCS_SEARCH`, ~10MB each, built from `plain_text`), lazy-loaded via a `<script>` tag on the first query so it works over `file://`. Code blocks get rule-based syntax highlighting in the browser (`pre[data-lang]` -> `tk-*` spans). Pages with no Korean version are rendered under `ko/` from the English text with a `.notice` banner. Also supports GitHub-style callouts (`> [!NOTE]`), tables, nested lists and code blocks.

The `Renderer` split is deliberately a set of **mixins that share state through `self`**, not independent components: methods were moved verbatim, so output is byte-identical (checked on all 451 site files). Mixins must not hold class-level data and must not define the same method twice; `tests/test_md_modules.py` enforces both, and that each module imports alone and a fresh `Renderer` owns exactly the documented state. Add new state to `Renderer.__init__` and to the mixin header comment.

**Heading ids**: official Korean pages keep the English anchors in their links (e.g. `#agents-md`), so the Korean `Renderer` is given `hint=` the English page's `(level, id)` list and reuses those ids in order; on a level mismatch it falls back to the normal slug rule for the rest. The converter prints how many Korean pages matched fully (expect all).

**Link classification** (`resolve_links` in the fetcher) for docs URLs that were linked but not collected: `redirects` (old URL alias), `_unlisted` (added as a hidden page), `non_page_links` (GET returns 405 or a non-docs response, e.g. MCP endpoints such as `/docs/mcp`), `unresolved_links` (any other failure, e.g. 404).

## Build behavior (`build_docs_snapshot.py`)
- Builds in `output/.building/` (`docs.json` + `site/`; the fetcher writes assets straight into `.building/site/assets`, so there is no second copy). Only if every page is fetched (English and Korean) and converted does `swap_site` replace `output/site/` (old one is parked as `site.old` and restored if the swap fails), then `save_history` runs, `.building` is deleted and `output/index.html` (redirect to `site/index.html`) is rewritten. On failure the existing site stays untouched. No zip is produced.
- Output layout: `output/{index.html, site/, history/}`. One site, one source of truth: `history/YYYY-MM-DD.json.gz` (the gzipped `docs.json`) and `history/YYYY-MM-DD.diff` (full per-page unified diff vs. the comparison target; omitted when nothing changed). `prune_history` keeps the newest `KEEP_HISTORY = 30` dates (counts dates, not calendar days). There is no per-date folder and no uncompressed `docs.json` outside `.building`.
- `find_previous` and `docs_changes.change_data` run **before** conversion. The data goes to `docs_json_to_html.main(..., changes=)`, which writes `en/changes.html` and `ko/changes.html` (the normal `Renderer` on `changes_markdown`; not in the nav or the search index; every other page's footer links to it; without `changes=` there is no page and no link, e.g. standalone converter runs). The log puts `변경 요약` right after the collection summary and the long link lists at the end in `링크 상세`, because the change summary is the tool's main output.
- After converting, `docs_verify.check` runs on the new site; any violation aborts the build before `swap_site`. Stale links also get a "manual check" hint (`nearest_id`, word overlap ≥ `HINT_MIN` 0.6) in the log; hints never relink.
- `swap_site` retries `os.replace` on `PermissionError` (`SWAP_RETRIES` × `SWAP_DELAY`): on Windows a browser/IDE/Explorer/local server can hold `output/site` for a while, which once failed a full build at the very last step. After the retries it raises with a message naming the likely causes; the old site stays.
- No internet → exit 1 without touching the site; only a log file is written.
- `docs_json_to_html.main()` returns the number of links pointing to missing files (both languages); non-zero fails the build.
- The change summary uses `find_previous` **before** pruning. Priority: latest history strictly older than today > latest non-today legacy folder `output/YYYY-MM-DD/docs.json` > today's legacy folder. Legacy folders (made by the previous layout) are deleted by `remove_legacy_dirs` after the first successful build. So a same-day re-run still compares against yesterday once history exists. The log's change summary is English-only (page URLs); Korean changes appear in `ko/changes.html` (official Korean text, not translated) and in the diff file as `ko/…`.

## Logs
- One file per run (success, failure or error): `logs/YYYY/YYYY-MM-DD_HHMMSS.log` (e.g. `logs/2026/2026-11-26_153729.log`); same-second collisions get `_2`. Logs are independent of `output/`, so pruning never deletes them.
- Contents: result, start/end/duration, collection summary (pages, Korean pages / missing Korean, assets, aliases, hidden pages, non-doc/unresolved links), change vs. previous history, pruned legacy folders and history, traceback on error, the `LOG_GUIDE` table, full console output. Log text is Korean.
- `LOG_GUIDE` (in `build_docs_snapshot.py`) is appended to every log and explains what each section signals (new feature, deprecation/move, behavior change). Keep it in sync if you add or rename log sections.
- The log's change summary points to the full diff file and reports counts of added/removed/changed pages and, per changed page, the character delta, new/removed/edited sections and up to 3 added/removed representative lines (140 chars). It is a rule-based section/line comparison, not a full diff or prose summary — treat it as clues, not conclusions.

## Invariants when editing
- `docs_markdown.anchor_key` (Python) and `DocsLib.anchorKey` (`site_src/lib.js`) must keep the same rule (URL-decode, lowercase, letters/digits only; a malformed `%` sequence is not decoded in either). `tests/test_anchor_sync.py` feeds both the same inputs (including malformed and Unicode edge cases) and compares. The site's heading-id rules differ (`.`, `/`, `’`), so `nav.js` falls back to this punctuation-insensitive match.
- **Anchors are settled at build time** (`resolve_anchors` / `resolve_anchor`), after every page's ids are known. Docs links with a `#frag` (and same-page `#frag` links) are rewritten to a real id: `exact` → `key` (case/punctuation only) → `strict` (every word of the frag is in exactly one id, so a heading lengthened upstream is followed; ambiguity is never guessed) → `stale`. A `stale` link drops its anchor, opens the page top and gets `class="stale-anchor"` + a `title` (`UI_TEXT["stale"]`). `Renderer(defer_anchors=True)` leaves `href="\x01N\x01"` markers for this; the default (used by tests) writes `rel#frag` directly. The totals and the lists go to `docs_anchors.REPORT`, which the build copies into the log's `링크 검증` section. About 190 unique stale (page, anchor) pairs, linked from about 450 places per language, are expected at last run: the target section no longer exists upstream. A jump in that number means upstream restructured.
- Accordions (`> [accordion] Title`) get an `id` from the same slug rule as headings (shared dedupe counter); Korean accordions borrow the English page's accordion ids in order (`acc_hint`), counted separately from headings. `reveal()` in `nav.js` opens the `<details>` on navigation.
- Site HTML/CSS/JS are real files in `site_src/` (not Python strings), read by `docs_site.py`. Edit those, never the generated files under `output/`. `page.html` is a `string.Template`: slots are `${name}` and a literal `$` must be written `$$`. Put decisions and calculations in `lib.js` (DOM-free, unit-tested with `node --test`); `app.js`/`search.js`/`highlight.js` should only touch the DOM. `lib.js` must stay first in `JS_PARTS` and must end with the `module.exports` guard so Node can `require` it.
- Official Korean text is never translated or edited. UI wording in `UI_TEXT` is the only hand-written Korean; do not add translated doc content.
- URL comparison rules belong only in `docs_common.norm` / `slug`; both the fetcher and the converter import them.
- Assets are stored once. The converter copies assets only when `<out>/assets` does not exist yet (standalone runs); otherwise it assumes the fetcher already saved them there. Page `assets` values are site-root-relative (`assets/file`).

## Environment notes
- Sources and logs are UTF-8 with Korean text. PowerShell `Get-Content` shows them garbled; use the Read tool or `-Encoding utf8`.
- `.mcp.json` points at a local IntelliJ (`idea`) MCP server; it is mostly irrelevant for this Python project. `.idea/`, `__pycache__/` and `.claude/settings.local.json` are git-ignored.

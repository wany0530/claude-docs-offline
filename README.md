# claude-docs

[Claude Code 공식 문서](https://code.claude.com/docs)를 **오프라인 스냅샷**으로 만드는 도구입니다.
인터넷에 잠깐 연결해 한 번 실행하면, 그날 기준의 문서 전체를 원문 JSON과 오프라인 HTML 사이트로 저장합니다.

- 공식 사이트와 같은 화면 구성(상단 탭, 사이드바, 검색, 탭·아코디언·카드)으로 **영어판과 공식 한국어판**을 모두 만듭니다. 한국어는 번역이 아니라 공식 사이트의 한국어 문서(`/docs/ko/`) 원문을 그대로 수집한 것입니다.
- 파이썬 표준 라이브러리만 사용합니다 (설치할 패키지 없음).
- 서버 없이 `file://`로 열립니다.
- 실행할 때마다 직전 이력 대비 **무엇이 바뀌었는지** 로그로 남깁니다.

## 요구 사항

- Python 3.9 이상
- 실행하는 동안만 인터넷 연결

## 사용법

```
python build_docs_snapshot.py
```

약 10초~2분 걸립니다. 어느 폴더에서 실행해도 같습니다.

1. 인터넷에 연결합니다.
2. 위 명령을 실행합니다.
3. 연결을 끊고 `output/index.html`을 엽니다. 최신 사이트의 영어 Overview로 이동하며, 상단의 언어 선택(English / 한국어)으로 같은 페이지의 다른 언어판으로 바꿉니다.

출력·로그 폴더를 바꾸려면 `python build_docs_snapshot.py [출력폴더] [로그폴더]`로 지정합니다.

## 결과물

```
output/
├─ index.html              site/ 로 이동하는 바로가기
├─ site/                   최신 오프라인 사이트 (브라우저로 여는 유일한 사본)
│  ├─ en/  ko/             페이지별 HTML (영어판, 공식 한국어판)
│  ├─ assets/              문서의 이미지·동영상 (이 한 곳에만 있음)
│  └─ style.css, nav.js, nav-data-*.js, search-data-*.js
└─ history/                원본 데이터 (유일한 사본, 최근 30회분)
   ├─ YYYY-MM-DD.json.gz   그날의 docs.json (페이지별 분류, 영어·한국어 본문, 메뉴 이름 등)
   └─ YYYY-MM-DD.diff      직전 이력 대비 바뀐 페이지의 unified diff (변경이 있을 때만)
logs/
└─ YYYY/YYYY-MM-DD_HHMMSS.log   실행 1회당 로그 1개
```

- 사이트와 원본을 한 벌씩만 둡니다. 압축하지 않은 `docs.json`이나 날짜별 사이트 폴더, 에셋 복사본은 만들지 않습니다.
- `history/`에는 날짜별 `docs.json`을 gzip(약 6MB)으로 **최근 30회분** 보관하므로 과거 본문을 복원하고 비교할 수 있습니다. 보관 개수는 `build_docs_snapshot.py`의 `KEEP_HISTORY`입니다.
- 사이트: 공식 사이트처럼 상단 탭 + 현재 탭의 사이드바(페이지 이름 필터 포함), 헤더의 **본문 검색**(`Ctrl K`, 현재 언어의 색인), 오른쪽 **이 페이지 목차**(스크롤 따라 강조, 좁은 화면에서는 본문 위의 접는 목차로 바뀜), 사이드바의 **공식 사이트와 같은 순서**(일반 페이지 사이에 끼는 하위 그룹까지. 공식 HTML의 순서를 `docs.json`의 `nav_order`로 받아 형제 항목만 재배열), **페이지 복사** 버튼(원문 마크다운), 코드 **구문 강조**(bash·json·python·js/ts·yaml·toml·powershell)와 복사 버튼, 본문의 탭·아코디언·카드 컴포넌트, 다크 모드 자동 대응, 좁은 화면용 메뉴 토글이 있고, 각 페이지 하단에 원문 주소와 스냅샷 날짜, 그리고 **변경 내역** 링크가 있습니다. 변경 내역(`en/changes.html`, `ko/changes.html`)은 지난 이력과 비교해 추가·삭제·바뀐 페이지와 새·삭제·수정된 섹션, 바뀐 줄을 보여 주며, 한국어판은 번역이 아니라 공식 한국어 본문의 변경을 보여 줍니다(영어만 바뀌고 한국어판은 아직 그대로인 페이지는 한국어 변경 내역에 나오지 않음). 목차에 없는 숨은 페이지도 함께 수집하며(목차의 `Unlisted`), 옛 주소로 걸린 링크는 새 주소로 연결됩니다.
- 한국어판이 없는 페이지(현재 `changelog`, `claude-tag`: 공식 사이트가 외부 주소로 넘김)는 한국어 사이트에서 **영어 원문**을 안내 문구와 함께 보여 줍니다. 번역하지 않습니다.
- 로그에는 결과, 수집 요약, **직전 이력 대비 변경 요약**(앞쪽, 사이트의 변경 내역과 같은 계산), 링크 검증 요약, 콘솔 출력이 들어갑니다. 길어질 수 있는 링크 목록은 로그 뒤쪽의 "링크 상세"에 있습니다. 바뀐 내용의 전문은 `history/YYYY-MM-DD.diff`에 있고, 로그에는 그 경로가 적힙니다.
- `output/`과 `logs/`는 git에 올라가지 않습니다(`.gitignore`). 필요하면 직접 실행해서 만드세요.
- 이전 버전이 만든 `output/YYYY-MM-DD/` 폴더가 있으면 첫 실행 때 비교 기준으로 한 번 쓰고 삭제합니다.

## 안전장치

- 아래 경우에는 기존 사이트를 건드리지 않고 종료 코드 1로 끝나며, 로그 파일만 남습니다.
  - 인터넷에 연결되지 않음
  - 수집에 실패한 페이지가 하나라도 있음 (영어판, 한국어판 모두. 한국어판이 공식적으로 없는 것은 실패가 아님)
  - 변환한 HTML에 없는 파일을 가리키는 내부 링크가 있음
  - 예상하지 못한 오류 (트레이스백이 로그에 기록됨)
- 빌드는 `output/.building/`에서 하고, 모든 페이지 수집·변환이 성공했을 때만 `site/`를 통째로 교체합니다. 교체 중 실패하면 기존 `site/`를 되돌립니다.
- 이미지·동영상 다운로드 실패는 빌드를 멈추지 않습니다. 로그의 수집 요약(에셋 실패 수)에만 기록됩니다.
- 같은 날 다시 실행하면 그날 사이트와 이력을 덮어씁니다. 비교 대상은 **오늘 이전의 가장 최근 이력**이라, 다시 실행해도 어제 대비 변경이 그대로 나옵니다. (오늘 이전 이력이 아직 없으면 옛 구조의 날짜 폴더나 오늘 이력과 비교하므로 변경이 거의 없게 나올 수 있습니다.)

## 구성

| 파일 | 역할 |
|---|---|
| `build_docs_snapshot.py` | 통합 진입점. 수집 → HTML 변환 → `site/` 교체 → 이력·diff 저장 → 로그 |
| `docs_fetch_json.py` | `llms.txt`에서 페이지 목록을 읽어 영어 원문(.md), 공식 한국어판(`/docs/ko/`), 에셋을 받아 JSON으로 저장 |
| `docs_json_to_html.py` | JSON(.gz 가능)을 영어·한국어 정적 HTML 사이트로 변환하는 진행 순서 (실제 일은 아래 모듈이 함) |
| `docs_markdown.py` | 직접 만든 마크다운 → HTML 변환기 (탭·아코디언·카드 컴포넌트 포함) |
| `docs_anchors.py` | 본문의 `#앵커` 링크를 실제 섹션에 맞춰 확정, 검토 장부 대조 |
| `docs_changes.py` | 두 스냅샷의 변경 계산(로그 요약과 사이트의 변경 내역 페이지가 같은 계산을 씀) |
| `docs_site.py` | 화면 문구, 메뉴 트리, 주소 표, `site_src/` 파일 읽기 |
| `site_src/` | 사이트의 실제 소스: `style.css`, `page.html`, JS(`lib.js` 계산 함수, `app.js` 메뉴·목차·복사, `search.js`, `highlight.js`) |
| `docs_diff.py` | 보관된 이력 두 개를 비교해 페이지별 diff 출력 (빌드도 이 모듈로 diff 저장) |
| `docs_common.py` | 수집기·변환기가 공유하는 URL 규칙, 콘솔 UTF-8 설정 |
| `tests/` | 표준 라이브러리 `unittest` 테스트 (네트워크 불필요). Node가 있으면 `tests/js/`의 JS 테스트(`node --test`)와 파이썬·JS 앵커 규칙 비교도 함께 실행하고, 없으면 건너뜁니다 |

단계별로 따로 실행할 수도 있습니다.

```
python docs_fetch_json.py tmp/docs.json tmp/site/assets
python docs_json_to_html.py tmp/docs.json tmp/site
```

이미 보관된 이력으로 사이트만 다시 만들 수도 있습니다(네트워크 불필요, 에셋은 출력 폴더에 이미 있으면 복사하지 않음).

```
python docs_json_to_html.py output/history/YYYY-MM-DD.json.gz 새폴더 output/site/assets
```

보관한 두 날짜의 차이를 보려면(페이지 slug는 선택, `en/hooks`·`ko/hooks`처럼 언어 접두어를 붙임. 한국어는 두 이력 모두에 한국어 데이터가 있을 때만 비교):

```
python docs_diff.py 2026-11-20 2026-11-27 ko/hooks
```

테스트:

```
python -m unittest discover tests                              # 단위 테스트 전체 (네트워크 불필요, Node가 있으면 JS 테스트 포함)
cd tests/e2e && npm ci && npx playwright install chromium && npm test    # 브라우저 E2E (개발용, 아래 설명)
DOCS_REAL=1 python -m unittest discover tests -p "test_realdata.py"      # 받아 둔 실제 데이터로 불변식 확인 (PowerShell: $env:DOCS_REAL=1)
```

- **단위 테스트**(약 110개): 마크다운 변환기, 앵커 확정, 수집기(가짜 네트워크), 빌드 전체(`build_docs_snapshot.main`을 가짜 수집기로 돌려 성공·실패 경로마다 "기존 사이트는 그대로"를 확인), 독립 검증기, 두 언어 사이트 출력. Node가 있으면 `tests/js/`의 `site_src/lib.js` 테스트(`node --test`)와 파이썬·JS 앵커 규칙 비교도 함께 돕니다.
- **브라우저 E2E**(`tests/e2e`, Chromium, 개발할 때만 필요): 가짜 문서 6쪽으로 만든 고정 사이트를 열어 메뉴·목차·탭·아코디언 이동·검색·복사·구문 강조·모바일 레이아웃을 확인하고, 서버 없이 `file://`로 여는 경우도 확인합니다. 도구 자체는 계속 표준 라이브러리만 씁니다. `@playwright/test`는 1.61.1로 고정돼 있어 Chromium 리비전 1228을 씁니다.
- **접근성**: 키보드만으로 쓸 수 있게 '본문으로 건너뛰기' 링크, 포커스 윤곽선, 본문 탭의 WAI-ARIA 패턴(화살표·Home·End), 검색 창의 포커스 가두기와 화살표 이동·Esc 복귀를 넣었고, `axe-core`(WCAG 2 A/AA)가 밝은·어두운 테마, 검색 창, 모바일 상태에서 위반 0건인지 E2E로 확인합니다. 한계: 스크린 리더로 직접 들어 본 것은 아니고(자동 검사와 키보드 동작만 확인), 색 대비는 axe가 판정한 요소만 보장합니다.
- **실제 데이터 불변식**: `output/history`가 있을 때만 켜지며(기본은 건너뜀), 없는 파일 0, 한국어 id 일치, 독립 검사 위반 0, 장부에 없는 새 보정 0과 끊김·보정 수의 느슨한 상한(`tests/real_data_limits.json`)을 확인합니다. 업스트림이 바뀌어 새 보정이 생기면 실패하는데, 이는 오류가 아니라 검토 신호입니다.
- **Python 3.9 이상**이라는 주장은 두 가지로 지킵니다. 3.12 이상 전용 f-string 문법을 토큰으로 찾는 정적 테스트(`tests/test_compat.py`)와, GitHub Actions(`.github/workflows/test.yml`)의 3.9·3.14 매트릭스입니다. 후자는 저장소에 push해야 실제로 돌며, 이 문서를 쓴 시점에는 아직 한 번도 실행되지 않았습니다.

콘솔 인코딩:

스크립트는 시작할 때 콘솔을 UTF-8·줄 단위 버퍼로 바꿔서 한글이 깨지지 않고 출력 순서도 유지됩니다. 오래된 PowerShell 5.1에서 직접 눈으로 볼 때 깨지면 `[Console]::OutputEncoding=[Text.Encoding]::UTF8`을 먼저 실행하세요.

## 오프라인에서 되는 것과 안 되는 것

2026-11-27 사본(222쪽 × 2개 언어)으로 측정한 값입니다.

- **되는 것**: 화면을 그리는 데 필요한 원격 리소스(이미지·동영상·CSS·글꼴)가 **0개**입니다. 이미지·동영상 73개는 `assets/`에 있고 글꼴은 시스템 글꼴입니다. 서버 없이 `file://`로 열립니다. 메뉴, 목차, 검색, 복사, 다크 모드, 변경 내역이 모두 오프라인에서 동작합니다.
- **안 되는 것**: 본문 안의 외부 링크 약 3,480개(claude.com 564, claude.ai 532, platform.claude.com 506, github.com 410 등)는 인터넷이 있어야 열립니다. 각 페이지 하단의 "원문" 링크도 마찬가지입니다. `https://code.claude.com/docs/mcp` 같은 문서 페이지가 아닌 주소도 외부 링크로 남습니다.
- **크기**: 사이트 약 80MB(에셋 포함), 이력은 하루 약 6MB(gzip)입니다. 검색 색인은 영어 9.7MB, 한국어 11.5MB입니다.
- **속도**: 이 PC(Chromium, `file://`, 색인을 처음 읽는 검색)에서 첫 검색은 디바운스 150ms를 포함해 약 0.3초였고 JS 힙은 40~47MB였습니다. 색인을 읽은 뒤 검색은 거의 즉시입니다. 느린 디스크에서는 더 걸릴 수 있습니다.
- **최신성**: 사본은 실행한 날 기준입니다. 자동으로 갱신하지 않으며 직접 실행해야 합니다. 어느 날짜 기준인지는 각 페이지 하단과 변경 내역 페이지에 있습니다.

## 알려진 한계

- 구문 강조는 규칙 기반의 간단한 방식이라 언어 문법을 완전히 해석하지는 않습니다. 지원하지 않는 언어는 색 없이 표시됩니다.
- 본문 검색은 부분 문자열 일치(공백으로 나눈 단어 모두 포함)이며 형태소 분석이나 오타 보정은 없습니다. 첫 검색 때 현재 언어의 색인(약 10MB)을 한 번 불러옵니다(위 '속도' 참고). 한글은 한 글자 검색어도 됩니다.
- 공식 사이트의 "Ask Assistant", 로고·웹폰트 등 온라인 요소는 없습니다. 글꼴은 시스템 글꼴을 씁니다.
- 빌드는 만든 사이트의 HTML을 변환기와 무관하게 다시 읽어(`docs_verify.py`) 모든 링크의 대상 파일·앵커, 중복 id, 이미지 파일을 검사하고, 위반이 있으면 기존 사이트를 건드리지 않고 중단합니다. 따로 확인하려면 `python docs_verify.py output/site`. 이 검사는 "대상이 있다"까지만 보장하며, 단어 일치로 이어 준 링크가 의미상 맞는지는 `reviewed_anchors.json`에 검토 기록(현재 91건)을 두고 새 보정이 생기면 로그에 "검토 필요"로 알립니다.
- Windows에서 브라우저·IDE·탐색기가 `output/site`를 열고 있으면 마지막 교체 단계가 거부될 수 있어 몇 번 다시 시도하고, 그래도 안 되면 원인을 알리고 기존 사이트는 그대로 둡니다. 빌드 전에 사이트를 보던 프로그램을 닫으세요.
- 본문의 `#앵커` 링크는 빌드할 때 실제 섹션(헤딩·아코디언)에 맞춰 확정합니다. 제목이 길어진 정도는 단어가 겹치는 섹션이 하나뿐일 때만 따라가고, 공식 문서에서 섹션이 사라지거나 이름이 크게 바뀐 링크(언어별 약 450건)는 페이지 처음으로 연결하며 점선 밑줄과 안내 문구로 표시합니다. 건수와 목록은 빌드 로그의 "링크 검증"에 남습니다. 한국어 본문의 링크도 영어판과 같은 앵커를 쓰므로, 한국어 페이지의 헤딩·아코디언 id는 같은 페이지 영어판 id를 그대로 씁니다.
- 로그의 변경 요약은 섹션(헤딩)·줄 단위의 규칙 기반 비교이며 문장 요약이 아닙니다. 확정이 아니라 단서로 보고, 전문은 `history/*.diff`나 `docs_diff.py`로 확인하세요.
- 수집하지 않는 것: GitHub 저장소 `anthropics/claude-code`의 `CHANGELOG.md`, `plugins/`, `examples/` (변경이 너무 잦거나 문서와 중복).
- 스냅샷 날짜는 실행한 PC의 로컬 날짜 기준입니다.
- 변경 요약(로그)은 영어판 기준입니다. 한국어판의 변경은 사이트의 `ko/changes.html`과 `history/*.diff`의 `ko/…` 항목에서 봅니다.
